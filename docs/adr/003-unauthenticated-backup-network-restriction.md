# ADR-003: 인증 없는 백업 UI의 네트워크 제한

- **상태**: accepted
- **날짜**: 2026-08-22
- **결정자**: agent + human (T-014, 적대적 리뷰 James/Popper)
- **컨텍스트**: PostgreSQL `.dump` 생성·목록·다운로드·복원을 웹 UI에서 직접 수행할 수 있어야
  한다는 요구가 있었다. 이 API는 destructive(복원 시 기존 데이터 교체)하고, 별도 앱 레벨 인증을
  추가하면 단일 운영자 환경에서 UX 복잡도만 늘어난다는 판단이 있었다. 적대적 리뷰(James/Popper)
  에서도 무인증 backup/restore API 노출이 P0/P1 지적 대상이었다.
- **결정**: 앱 레벨 인증(로그인/토큰)은 추가하지 않는다. 대신 (1) 복원 전 자동 backup을 응답에
  포함하고, (2) UI에 destructive operation 경고를 명시하고, (3) gateway/private network 보호
  (`TRUSTED_HOSTS_CSV`, 운영 CORS 제한, 외부 노출 최소화)를 실제 운영 설정과 런북에 남긴다.
  이 결정은 사용자의 명시적 요구이며, 무인증 상태를 "숨은 위험"이 아니라 문서화된 전제로 취급한다.
- **근거**: 단일 운영자 + 내부망/게이트웨이 경계라는 실제 운영 모델에서는 네트워크 계층 제한이
  앱 인증보다 실효성이 크고 구현·운영 비용이 낮다. 자동 backup + destructive 경고는 실수로 인한
  데이터 손실 위험을 인증 없이도 낮춘다.
- **결과 (긍정)**: 백업/복원 UI가 별도 로그인 흐름 없이 바로 동작해 운영자가 즉시 사용할 수
  있고, `EXERCISE_LIVE_BACKUP=true` exact live E2E로 실제 dump 생성까지 검증했다.
- **결과 (부정)**: 게이트웨이/네트워크 경계 설정이 잘못되면(예: `TRUSTED_HOSTS_CSV` 실수,
  CORS 과다 허용) 이 API가 외부에 그대로 노출된다. 앱 자체에는 이를 막는 2차 방어선이 없다.
- **후속**: 배포 환경을 바꾸거나 새 호스트로 이전할 때는 `TRUSTED_HOSTS_CSV`/CORS 설정을
  먼저 확인하고, 무인증 백업 API가 실제로 내부망/게이트웨이 뒤에 있는지 확인한 뒤에만 배포를
  완료 처리한다. 앱 레벨 인증이 필요해지면(예: 다중 운영자, 공개 접근 요구) 이 ADR을
  superseded 상태로 바꾸고 새 ADR을 작성한다.
